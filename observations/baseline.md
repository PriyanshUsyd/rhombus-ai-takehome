**Summary.** On the clean-ish baseline input (250 rows with known, injected defects), the AI-built pipeline produced the expected **218 rows**:
- every duplicate removed;
- every rejection rule applied exactly;
- 13 of 14 per-rule checks passed.

Two defects remain and appear in every later run:
- the 3 missing names are written as the **text `None`**;
- **70 price/total cells lose a trailing zero** (`2151.20` → `2151.2`).

Runs 1, 2 and 4 are **byte-identical**, which is the determinism evidence. Every drift case is compared against run 4.

## 10. Three verdicts

Not a semantic case; this section doesn't apply.

## 11. Severity

- **`None` names: High** (rubric: silent incorrect output; scope: 3 of 218 rows). The pipeline invents a value (`None`) for missing data, which the prompt forbids ("Never invent or guess a value"). It reaches the destination with no warning: **silent incorrect output**. Small scope: 3 of 218 rows. A downstream consumer would see customers literally named "None", and null checks would miss them.
- **Trailing zeros: Low.** Only the formatting is wrong; the values are correct and easy to reformat (safe recovery).

## 12. Reproduction steps

1. In a Rhombus project, upload `datasets/baseline.csv` via Data Input → "From Device".
2. Build the pipeline with the AI builder using Prompt 1 from `datasets/ai-builder-prompts.md`. Set Data Output to Azure Blob Storage `output`, CSV.
3. Trigger a manual ▶ run and download the new `RhombusAI_output_*.csv` from `output`.
4. Validate:
   ```
   python data-validation/validate.py --scenario baseline --input datasets/baseline.csv --output <file> --report <report.json>
   ```
5. Repeat steps 3–4 and add `--baseline-output <first file>` to check determinism.
